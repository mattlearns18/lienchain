## Acceptance criteria

1. ✓ **Patient net > 0 scenario** — Settle Now confirm modal shows "Patient Net Recovery" row in the breakdown (muted). Below the breakdown: amber block "⚠ Patient disbursement not yet recorded — $X owed to patient" with "Mark Patient Disbursed" button.
2. ✓ **Mark Patient Disbursed modal** — Clicking opens `PatientDisbursalModal` with Amount prefilled to `waterfall.patientNet`, Date to today, Reference/Confirmed by empty. Submit writes record, strip flips to green "✓ Patient disbursed — $X on {date} by {initials}".
3. ✓ **Persistence** — `case.patientDisbursement` written to `lienchain:cases` via `savePatientDisbursement`. Survives reload.
4. ✓ **Update flow** — Green strip shows "Update" button; clicking re-opens `PatientDisbursalModal` with `initial` prop populated from saved values.
5. ✓ **Patient net = 0 scenario** — `patientNet > 0` guard prevents rendering the breakdown row, the strip, and the button. No signal at all.
6. ✓ **Settle Now not gated on patient disbursement** — `disabled` on the Execute button is only tied to fiat receipt. Patient disbursement strip is informational; does not disable the execute button.
7. ✓ **Operator-only display** — All patient disbursement UI is gated on `isOperatorView`. Direct `/attorney/:caseId` and `/attorney/demo` routes leave `isOperatorView` defaulting to `false`, so nothing renders. Matches CLAUDE.md §4 separation rule.
8. ✓ **Liens tab pill** — `caseObj.patientNetRecovery > 0` (stored at settlement) drives the pill. `patientDisbursement` null → amber "Patient ⌛"; exists → green "Patient ✓". No pill when patientNetRecovery is 0 or not set (cases settled before Phase 12, or pool exhausted).
9. ✓ **Build clean** — Two files changed, no new imports beyond existing components, no structural changes to routing or data flow.

## Deviations from spec

- **`PatientDisbursalModal` not inside `SettleModal`** — rendered at the main `AttorneyPreview` level alongside `FiatReceiptModal` and `SettleModal`, not embedded inside SettleModal. When the user clicks "Mark Patient Disbursed" from within the Settle Now modal, both overlays are present simultaneously (patient modal renders after settle modal in the DOM, so it sits on top). This is the same pattern as other modals in this codebase and is functionally correct. An embedded approach would have required more state plumbing inside SettleModal.
- **`patientNetRecovery` not shown in the Liens tab pill for cases settled before Phase 12** — The pill only appears for cases where `patientNetRecovery` was stored during settlement (i.e., settled after this commit). Pre-existing settled cases won't show the pill even if they had patient net. This is expected — the data wasn't captured historically. The pill will correctly appear for all future settlements.
