## Part A — Bucket the seed mocks

Live QA on Commit 1 surfaced that the 4 seed mocks (`PI-LIEN-2025-11-001`, `PI-LIEN-2026-04-TX001`, `PI-LIEN-2026-04-NV001`, `PI-LIEN-2026-04-IN001`) contribute to Total Deployed Capital and the 9-count but are absent from both the Active (3) and Settled (2) tile sub-counts. They're sitting in a no-status bucket.

Fix at the analytics derivation layer in the same `deriveLienAnalytics` helper Commit 1 introduced. Seed mocks have `status === 'Active'` per the current mock data (a Phase 4 regression that was never reverted). For Phase 7's analytics purposes, the cleanest read is to **treat them as Settled** with derived recovery, since visually they were settled in Phase 1-3 with two TX hashes each and they appear in Settlement Ledger.

```js
function deriveLienAnalytics(lien) {

  // existing code identifies them; a regex on lien.id is fine).
  const isSeedMock = /^PI-LIEN-\d{4}-\d{2}-/.test(lien.id);

  // Seeds are visually settled (two TX hashes in mock data, appear in Settlement
  // Ledger), so for analytics purposes derive their status as Settled regardless
  // of the raw status field.
  const isSettled = lien.status === 'Settled' || isSeedMock;
  // ...existing derivation continues
}
```

Document the seed-mock heuristic with a code comment so future-you knows why
the override exists. This is consistent with the Phase 7 plan's "Legacy / mock

```jsx
  )}

```

### Data derivation

```js
const recoveryData = useMemo(() => {
  const settled = enrichedLiens.filter(l => l.derivedStatus === 'Settled');
  if (settled.length === 0) return [];

  // Bucket by YYYY-MM of settledAt
  const buckets = new Map();
  for (const lien of settled) {
    const key = lien.settledAt.slice(0, 7); // 'YYYY-MM'
    if (!buckets.has(key)) buckets.set(key, { recovery: 0, purchase: 0 });
    const b = buckets.get(key);
    b.recovery += lien.recovery;
    b.purchase += lien.purchasePrice;
  }

  return Array.from(buckets.entries())
    .sort(([a], [b]) => a.localeCompare(b))
    .map(([key, { recovery, purchase }]) => ({
      monthLabel: formatMonthLabel(key), // e.g. 'Sep 25', 'Oct 25'
      rate: purchase > 0 ? (recovery / purchase) * 100 : 0,
    }));
}, [enrichedLiens]);
```

### Data derivation

```js
const agingBuckets = useMemo(() => {
  const active = enrichedLiens.filter(l => l.status === 'Active');
  const totalAtRisk = sumBy(active, l => l.bill);

  const ranges = [
    { label: '0–90 days',     min: 0,   max: 90   },
    { label: '91–180 days',   min: 91,  max: 180  },
    { label: '181–365 days',  min: 181, max: 365  },
    { label: '365+ days',     min: 366, max: Infinity },
  ];

  const today = Date.now();
  return ranges.map(r => {
    const inBucket = active.filter(l => {
      const ageDays = Math.floor((today - new Date(l.ts).getTime()) / (1000 * 60 * 60 * 24));
      return ageDays >= r.min && ageDays <= r.max;
    });
    const bills = sumBy(inBucket, l => l.bill);
    return {
      label: r.label,
      count: inBucket.length,
      totalBills: bills,
      percentOfAtRisk: totalAtRisk > 0 ? (bills / totalAtRisk) * 100 : 0,
    };
  });
}, [enrichedLiens]);
```
