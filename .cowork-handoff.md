## Bug

`53783e5` is on origin/main and the deploy is live. On any TX-tagged case (e.g. the seed lien `PI-LIEN-2026-04-TX001`), the new **Texas hospital lien priority warning banner** does NOT appear above the SETTLEMENT WATERFALL section. Same shape of bug as the IN floor integration miss from `2f4afb7` → `1a92fba`: the implementation exists but isn't being rendered in the live path.

### Live reproducer

1. Open https://lienchain.vercel.app/dashboard
2. Switch to **Attorney View** tab
3. In the case selector dropdown, pick `PI-LIEN-2026-04-TX001 — TX Clinic (TX) — $18,400`
4. Look immediately above the `SETTLEMENT WATERFALL` heading (or anywhere on the case view).

### Observed (broken)

The existing **Texas 72-Hour Filing Alert** banner appears (this one shipped in Phase 4, copy: `⚠ Texas 72-Hour Filing Alert — lien is subject to a 72-hour rescission window under Texas law.`). It uses `.ap-flag-banner.ap-flag-orange`. That banner is fine and should stay.

But the NEW Phase 6 banner — the hospital lien priority warning, copy specified in `src/lib/markets.js` as `MARKET_INFO.TX.policy.priorityWarning`:

```
Texas hospital lien priority is not yet enforced in this waterfall. If a
hospital lien exists on this case, consult with the attorney before settling.
Under Tex. Health & Safety Code §55.005, hospital liens take priority over
other medical provider liens.
```

— is **absent**. A page-wide text search for `hospital lien priority` returns zero hits.

### Expected (correct)

A second banner appearing on any case where `≥1 clinic has market === 'TX'`, with the copy above pulled from `MARKET_INFO.TX.policy.priorityWarning`. Styling can match the existing `ap-flag-banner` look — the spec said "match the existing yellow `TX 72h Flag` style — a banner with a warning icon, single paragraph of copy, no dismiss button (it's a permanent advisory)."

The banner appears for ANY TX-touching case, including:
- Single-clinic TX cases (seed `PI-LIEN-2026-04-TX001`)
- Multi-clinic cases that include at least one TX clinic
- Single-clinic non-TX cases → **no** banner

## Likely root causes

Mirror the IN floor pattern:

1. The banner JSX was added to `src/pages/AttorneyPortal.jsx` but inside a code branch that doesn't render in the current code path (e.g. tied to a `selectedCase` variable that's set differently than expected).
2. The banner reads `MARKET_INFO[market].policy.priorityWarning` but the lookup gets `undefined` because the `market` field on the case-level object differs from the per-clinic `market` field. (Same kind of integration mismatch as Commit 2 — the data flowed without the `market` field.)
3. The component file was edited but the banner is gated behind a feature flag or a condition that hasn't fired yet.

When you fix it, please flag in the result file **which** of these was the actual cause, so we know what pattern to look for on future commits.

## Fix

Open `src/pages/AttorneyPortal.jsx`. Find the case view component (the one rendered when the user selects a case in Attorney View). Add the priority warning banner above the SETTLEMENT WATERFALL section.

```jsx
// Pseudo-code — adapt to the file's actual variable names and JSX structure.
const caseClinics = /* the clinics list AttorneyPortal already assembles */;
const hasTxClinic = caseClinics.some(c => c.market === 'TX');
const txWarning = hasTxClinic ? MARKET_INFO.TX.policy.priorityWarning : null;

// ...inside the JSX, BEFORE the existing ap-flag-banner for "Texas 72-Hour Filing Alert":
{txWarning && (
  <div className="ap-flag-banner ap-flag-amber ap-priority-warning">
    ⚠ {txWarning}
  </div>
)}
```

Style hint: the spec said match the `TX 72h Flag` style. The existing one uses `.ap-flag-banner.ap-flag-orange`. For the priority warning, use a slightly different shade (amber/yellow) so the two banners are visually distinguishable — but reuse the existing `.ap-flag-banner` base class so spacing/padding is consistent.
