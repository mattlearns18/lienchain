## Bug

The IN 20% clinic floor algorithm in `src/lib/waterfall.js` works correctly in isolation (27/27 unit tests pass). But in `src/pages/AttorneyPortal.jsx`, the rendered per-clinic recovery table does **not** apply the floor. The waterfall produces pure pro-rata recoveries regardless of clinic market.

### Live reproducer

1. Open https://lienchain.vercel.app/dashboard
2. In browser console, inject this state (or do it via UI — both work):

```js
const cases = JSON.parse(localStorage.getItem('lienchain:cases') || '[]');
const liens = JSON.parse(localStorage.getItem('lienchain:liens') || '[]');
liens.push({
  id: 'PI-LIEN-IN-REPRO',
  caseId: cases[0].caseId,
  market: 'IN',
  clinic: 'Indy Rehab Partners',
  bill: 10000,
  split: 70,
  status: 'Active',
  ts: new Date().toISOString(),
  attorney: cases[0].attorney,
  treatmentMonth: 'May',
  treatmentYear: '2026',
  tx1: '0'.repeat(64),
  tx2: null,
  flags: ['IN Non-Assignable'],
});
cases[0].clinicLienIds.push('PI-LIEN-IN-REPRO');
cases[0].status = 'Active';
liens.forEach(l => { l.status = 'Active'; l.tx2 = null; });
localStorage.setItem('lienchain:cases', JSON.stringify(cases));
localStorage.setItem('lienchain:liens', JSON.stringify(liens));
location.reload();
```

3. Switch to Attorney View, select the case (now 3 clinics: KC $5K + STL $7K + IN $10K = $22K total).
4. Set gross settlement to $4,000. Net = $2,680.
5. Pro-rata gives IN clinic `(10/22) × 2680 = $1,218.18`. Floor should be `$10,000 × 0.20 = $2,000`. Algorithm should raise IN to $2,000 and re-distribute the rest.

### Observed (broken)

- Indy Rehab Partners row: `$10,000.00 | $1,218.18 | 70% | $852.73 | $365.45` — **no `[FLOOR APPLIED]` tag**
- STL Ortho row: `$7,000.00 | $852.73 | 70% | ...`
- KC Pain row: `$5,000.00 | $609.09 | 70% | ...`
- Total: `$22,000.00 | $2,680.00 | $1,876.00 | $804.00`
- Note below table: `Pro-rata distribution applied — net pool insufficient to cover all bills in full.` (the *no-floor* pure pro-rata copy)

### Expected (correct)

- Indy Rehab Partners row: `$10,000.00 | $2,000.00 [FLOOR APPLIED] | 70% | $1,400.00 | $600.00`
- STL Ortho row: `$7,000.00 | $396.67 | 70% | $277.67 | $119.00`
- KC Pain row: `$5,000.00 | $283.33 | 70% | $198.33 | $85.00`
- Total: `$22,000.00 | $2,680.00 | $1,876.00 | $804.00` (totals tie out either way)
- Note: `Pro-rata distribution applied with Indiana 20% clinic floor enforcement. 1 IN clinic(s) raised to floor; remaining net pool re-distributed pro-rata.`

## Diagnosis I've already done

- The deployed JS bundle DOES contain the strings `clinicFloorPct` and `floorApplied` — so `src/lib/waterfall.js` and `src/lib/markets.js` are both in the build.
- The IN clinic's data in localStorage matches a wizard-minted lien's shape exactly (same keys, same types).
- `lien.market === 'IN'` is set correctly. The Liens tab parent row correctly shows the IN child clinic when expanded.
- Yet the rendered waterfall table is pure pro-rata. **Therefore the integration is the bug.**

## Likely root causes (rank-ordered by my guess)

1. **`AttorneyPortal.jsx` never calls `calcWaterfall`.** It still has the original inline pro-rata math from before Commit 2. The new function exists in the build but is dead code.
2. `AttorneyPortal.jsx` calls `calcWaterfall` but the input shape is wrong — e.g. it passes `clinics` without each clinic's `market` field, or passes `state: 'Indiana'` instead of `market: 'IN'`, so the algorithm doesn't recognize any IN clinic.
3. `AttorneyPortal.jsx` calls `calcWaterfall` and gets correct output, but the render loop ignores the `floorApplied` flag on each clinic and ignores the `note` / `poolExhausted` fields.

## Fix

Open `src/pages/AttorneyPortal.jsx`, find the `WaterfallSection` (or wherever the per-clinic recovery table is computed). Confirm:

1. **Invocation:** is `calcWaterfall({ netAvailable, clinics })` actually being called? If not, replace whatever inline pro-rata math is there with a single call to `calcWaterfall`.
2. **Input shape:** `clinics` must include each clinic's `market` field. The function reads `clinic.market === 'IN'` to identify IN clinics. Trace the data path — wherever the case's clinic list is assembled (looking up each `caseId`'s clinic liens from `lienchain:liens`), make sure the `market` field is preserved.
3. **Output consumption:** the table render needs to read `recovery.floorApplied` and append the `[FLOOR APPLIED]` tag for any clinic where it's `true`. The note below the table must use the conditional copy logic from the original handoff (pure pro-rata vs. floor-applied vs. pool-exhausted).

The unit test scenarios in `src/lib/__tests__/waterfall.test.js` already cover the math. Don't change those. Just make the integration in `AttorneyPortal.jsx` actually call `calcWaterfall` and render its output faithfully.
