## Part A — Data Model

### `lienchain:attorneys` (new localStorage key)

Array of attorney records. Shape:

```js
{
  id:        'ATTY-' + nanoid8(),     // e.g. 'ATTY-x7kP2qLm'
  name:      'Jane Smith, Esq.',
  firm:      'Smith & Associates',
  barNumber: 'MO-54321',              // optional
  email:     'jane@smithlaw.com',
  addedAt:   new Date().toISOString(),
}
```

If `nanoid` isn't a dependency, use `crypto.randomUUID().slice(0, 8)` or any short stable id generator. Pick one and stick with it.

### `case.attorneyAssignment` (new optional Case field)

```js
{
  attorneyId:  'ATTY-...',
  token:       crypto.randomUUID(),    // 36-char UUID
  sentAt:      new Date().toISOString(),
  acceptedAt:  null,                    // becomes ISO timestamp after first valid token visit (Commit 2 wires this)
}
```

Replaced wholesale on reassign or resend (resend = same attorneyId, new token, sentAt = now, acceptedAt = null). The existing `case.attorney` free-text field stays untouched.

## Part B — Attorney Registry Panel

Place inside the operator Dashboard tab, below the existing wallet panel and activity feed. New section. Match the existing analytics-card visual treatment from Phase 7 (`db-analytics-card` class).

**Card structure:**

```jsx
<div className="db-analytics-card">
  <div className="db-card-header-row">
    <h3 className="db-card-title">Attorneys</h3>
    <button className="db-btn-primary" onClick={openAddModal}>+ Add Attorney</button>
  </div>
  <p className="db-card-sub">PI attorneys provisioned to access case portals.</p>
  {attorneys.length === 0 ? (
    <div className="db-empty-state">No attorneys yet — add one to invite them to a case.</div>
  ) : (
    <table className="db-attorneys-table">
      <thead><tr><th>Name</th><th>Firm</th><th>Bar #</th><th>Email</th><th>Added</th><th></th></tr></thead>
      <tbody>
        {attorneys.map(a => (
          <tr key={a.id}>
            <td>{a.name}</td>
            <td>{a.firm}</td>
            <td>{a.barNumber || '—'}</td>
            <td>{a.email}</td>
            <td>{formatDate(a.addedAt)}</td>
            <td>
              <button onClick={() => openEditModal(a)}>Edit</button>
              <button onClick={() => deleteAttorney(a.id)} className="db-btn-danger">Delete</button>
            </td>
          </tr>
        ))}
      </tbody>
    </table>
  )}
</div>
```

**Add/Edit modal.** Standard form with name (required), firm (required), bar number (optional), email (required, basic email regex validation). Submit writes/updates the registry, closes modal.

**Delete behavior.** Confirm dialog ("Delete attorney {name}? This won't void invites already sent for cases."). On confirm, remove from registry but leave `case.attorneyAssignment.attorneyId` references intact — the UI just falls back to "Attorney removed from registry" in case views. Don't cascade-delete assignments.

## Part C — Invite Attorney Modal

**Entry points (two places):**

1. **Liens tab parent row.** Next to the existing "Attorney View →" button on each case row, add a new "Invite Attorney" button. Smaller, secondary styling (`db-btn-secondary`).
2. **Attorney View tab.** Inside the case header section (above the SETTLEMENT WATERFALL), add a small "Invite Attorney" button. Same styling.

If `case.attorneyAssignment` already exists, the button reads "Manage Invite" instead.

**Modal — fresh invite (no existing assignment):**

```
[Modal Title] Invite Attorney to {caseId}

Select an attorney from your registry, or add a new one.

[ Attorney picker dropdown — registered attorneys ▾ ]
[ + Add new attorney (opens the registry add modal inline) ]

[ Cancel ] [ Generate Invite ]
```

On "Generate Invite":
- Write `case.attorneyAssignment = { attorneyId, token: crypto.randomUUID(), sentAt: now, acceptedAt: null }`
- Switch the modal to the "Invite Sent" view below

**Modal — invite sent (after generation OR re-opened on case with existing assignment):**

```
[Modal Title] Invite Attorney to {caseId}

Invited: {attorney.name} ({attorney.firm}) on {sentAt}
Status:  {acceptedAt ? "Accepted on " + acceptedAt : "Awaiting acceptance"}

Invite link:
  https://lienchain.vercel.app/attorney/{caseId}?token={token}
[ Copy Invite Link ]
[ Open Email (mailto:) ]

[ Resend (new token) ]  [ Reassign to different attorney ]  [ Close ]
```

**Copy Invite Link** → `navigator.clipboard.writeText(url)`, brief "Copied!" inline confirmation that fades after 2 seconds.

**Open Email** → opens `mailto:{attorney.email}?subject={subject}&body={body}` where:

- subject: `Lien case access — {caseId}`
- body: 
  ```
  Hi {firstName from attorney.name},
  
  I'm sharing access to a personal-injury lien case in LienChain so you can review the settlement waterfall and submit reduction requests if needed.
  
  Case: {caseId}
  Open: https://lienchain.vercel.app/attorney/{caseId}?token={token}
  
  This link is unique to you — please don't share it. If you have questions or need a different attorney provisioned, let me know.
  
  — Sent via LienChain
  ```

Use `encodeURIComponent` on subject/body. Newlines as `%0D%0A` in the body.

**Resend** → regenerates token, updates sentAt, clears acceptedAt. Same attorney.
**Reassign** → goes back to the picker view, lets you select a different attorney. On submit, writes new assignment (new token, new attorneyId, sentAt now, acceptedAt null).

Position the pill next to the case ID, before the market badge. Match existing pill/badge styling from elsewhere on the page.

In this commit, `acceptedAt` is always null (Commit 2 wires the side that sets it). The "Accepted" branch is dead code until then but include the rendering logic so Commit 2 just flips state.
