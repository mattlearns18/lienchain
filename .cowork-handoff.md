## Part B — Real `Payment` transactions per clinic

Replace the mock hash generation in `handleSettled` (the per-clinic callback fired by `AttorneyPreview.jsx`'s sequential settlement flow) with actual XRPL Payment transactions.

**Pattern (matches `xrpl-tokenize.js`):**

```js
import { Client, Wallet, xrpToDrops } from 'xrpl';
import { getNetworkConfig } from '../lib/network';

async function executeSettlementPayment({ caseId, lien, clinic, amount }) {
  const { wssUrl, seed } = getNetworkConfig();
  const client = new Client(wssUrl);
  try {
    await client.connect();
    const wallet = Wallet.fromSeed(seed);

    const memoData = {
      caseId,
      lienId:     lien.id,
      clinicName: clinic.name,
      share:      amount,
      ts:         new Date().toISOString(),
    };

    const tx = {
      TransactionType: 'Payment',
      Account:         wallet.classicAddress,
      Destination:     clinic.destinationAddress,
      Amount:          xrpToDrops(amount.toFixed(6)),  // testnet: native XRP. Mainnet currency TBD — see Part C.
      Memos: [{
        Memo: {
          MemoType: Buffer.from('LienChain-ClinicPayout').toString('hex').toUpperCase(),
          MemoData: Buffer.from(JSON.stringify(memoData)).toString('hex').toUpperCase(),
        },
      }],
    };

    const prepared = await client.autofill(tx);
    const signed   = wallet.sign(prepared);
    const result   = await client.submitAndWait(signed.tx_blob);

    const txHash = result.result.hash;
    if (!txHash || txHash.length !== 64) {
      throw new Error(`Unexpected TX hash: "${txHash}"`);
    }
    return { success: true, txHash, ledgerIndex: result.result.ledger_index };
  } catch (err) {
    return { success: false, error: err.message };
  } finally {
    try { await client.disconnect(); } catch {}
  }
}
```

**Wiring into the existing settle flow:** in the sequential per-clinic settlement loop in `AttorneyPreview.jsx`, replace the line that generates a mock hash with a call to `executeSettlementPayment`. On success, write `tx2 = result.txHash`, `recovery = clinic.clinicShare`, `settledAt = now`, `status = 'Settled'` (existing fields from Phase 5 + 7). On failure, see Part C.

**Currency note:** testnet uses native XRP per the snippet above (`xrpToDrops(amount.toFixed(6))`). For mainnet, the `Amount` field may need to be an issued-currency object `{currency, issuer, value}` (RLUSD or USDC on XRPL when ready). Phase 9 doesn't pick the mainnet currency — but the code path should be ready for it. Add a `TODO(phase10): mainnet currency selection` comment near the `xrpToDrops` call.

**Test-mode note:** in development, if `clinic.destinationAddress` is missing for a clinic, fall back to writing a clearly-labeled "no-destination-skipped" sentinel so the UI surfaces the gap rather than silently succeeding with a mock. Better to fail loud than to silently mock in a commit whose whole point is replacing mocks.

## Part C — Partial-failure recovery

When `executeSettlementPayment` returns `{success: false, error}` for a clinic, the multi-clinic settlement loop must:

1. **Not abort the loop** — continue processing remaining clinics.
2. **Mark the failed clinic** — write `lien.settlementError = { message, attemptedAt }` to that lien. `tx2`, `recovery`, `settledAt` stay null. `status` stays `Active`.
3. **Bubble up to case rollup** — once the loop completes, recompute case status:
   - All clinic liens `Settled` → `case.status = 'Settled'` (existing rollup)
   - Some `Settled`, some `Active` or with `settlementError` → `case.status = 'Partial Settlement'` (new value)
   - None settled → `case.status = 'Active'` (unchanged)

**UI changes:**

- **Liens tab parent row badge:** new yellow/amber `[ Partial Settlement ]` pill alongside the existing Active / Settled pills. Position next to the case ID like the Invited/Accepted badges from Phase 8.
- **Expanded child rows on a Partial Settlement case:** each failed clinic row shows a small red error icon with the `settlementError.message` on hover/tooltip, and a `[ Retry Payout ]` button next to it. Succeeded clinics show their TX2 hash as today.
- **Settle Now button on a Partial Settlement case:** label flips to "Retry Failed Payouts" and only re-runs the clinics with `settlementError` or null `tx2`. Already-settled clinics are skipped (idempotent). Fiat receipt confirmation persists from the original settlement attempt — no need to re-confirm.

**Per-clinic Retry button behavior:**

- Confirm modal: "Retry on-chain payout for {clinic.name}? This will submit a new Payment transaction on {network}."
- On confirm: calls `executeSettlementPayment` for just that clinic. Clears `settlementError` on success, writes the success fields. Updates `settlementError` on failure. Recomputes case status afterward.
