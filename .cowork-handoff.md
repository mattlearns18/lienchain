## Part A — Data Model Additions

### Lien shape

Today the lien object includes: `{id, caseId, market, clinic, bill, split, ts, attorney, treatmentMonth, treatmentYear, tx1, tx2, flags, status, purchasePrice?}`.

Add two fields:
- `recovery: number | null` — LienCo dollar recovery on settlement. `null` while Active.
- `settledAt: string | null` — ISO timestamp at moment of settlement flip. `null` while Active.

### Where to write them

In the multi-clinic sequential settlement flow (the `onSettled` callback that's already being used to update `lien.tx2` and `lien.status = 'Settled'` per the Phase 5 cleanup commit `a24bb17`). For each clinic, write both fields in the same setLiens update:

```js
// inside handleSettled, when updating a single clinic lien:
{
  ...lien,
  status:     'Settled',
  tx2:        settlementHash,      // already does this
  recovery:   waterfallResult.lienCoShareForThisClinic,  // NEW
  settledAt:  new Date().toISOString(),                  // NEW
}
```

The per-clinic `lienCoShare` value comes from the `calcWaterfall` output that's already being computed for the settle modal (the same one that produces the table in AttorneyPreview). If the waterfall result isn't currently in scope of the settle callback, pass it through — don't recompute.

### Legacy / mock data defaults

The 4 seed liens in `Dashboard.jsx` mock data (PI-LIEN-2025-11-001, PI-LIEN-2026-04-TX001, PI-LIEN-2026-04-NV001, PI-LIEN-2026-04-IN001) all have `status: 'Settled'` but no `recovery` or `settledAt`. Same for any wizard-minted lien settled before this commit.

Handle at the data-source layer (wherever liens are read into the analytics computation):

```js
// inside the analytics derivation function (Part B)
function deriveLienAnalytics(lien) {
  const isSettled = lien.status === 'Settled';
  const purchasePrice = lien.purchasePrice ?? Math.round(lien.bill * 0.78);
  const recovery = lien.recovery ?? (isSettled ? Math.round(lien.bill * lien.split / 100) : null);
  const settledAt = lien.settledAt ?? (isSettled ? approxSettledAt(lien) : null);
  return { ...lien, purchasePrice, recovery, settledAt };
}

// approxSettledAt: take lien.ts + 6 months as a placeholder for legacy data
function approxSettledAt(lien) {
  const d = new Date(lien.ts);
  d.setMonth(d.getMonth() + 6);
  return d.toISOString();
}
```

Document these defaults clearly in a code comment so future-you knows they're estimates for backfilled data, not real values.

## Part B — KPI Tile Row on Dashboard

Replace the existing slim stats summary at the top of the Dashboard tab (currently shows count + total bill + avg split or similar) with a 6-tile row.

### Tiles (in order, left to right)

| # | Title (small caps) | Value | Sub-text | Computation |
|---|---|---|---|---|
| 1 | TOTAL DEPLOYED CAPITAL | `$X` formatted with commas | `across N liens` | sum(`lien.purchasePrice`) over ALL liens |
| 2 | TOTAL AT-RISK EXPOSURE | `$X` | `N active liens` | sum(`lien.bill`) where `lien.status === 'Active'` |
| 3 | RECOVERY RATE | `X%` (1 decimal) with up/down arrow | `lifetime, N settled` | sum(`lien.recovery`) / sum(`lien.purchasePrice`) × 100 over Settled liens. Up-arrow (green) if rate > 100%, down-arrow (red) if < 100%. Show `—` if no settled liens. |
| 4 | AVG DAYS TO SETTLE | `X days` | `N settled liens` | avg(days between `lien.ts` and `lien.settledAt`) over Settled liens. Round to whole days. Show `—` if none. |
| 5 | ACTIVE CASES | `N` | `· M clinic liens` | distinct case count where `case.status === 'Active'`, then M = sum of clinic liens across those cases |
| 6 | SETTLED CASES | `N` | `$X recovered` | distinct case count where `case.status === 'Settled'`, then X = sum of `lien.recovery` for liens on those cases |

### Derive analytics in one place

Add a small `useMemo` (or pure function called from the Dashboard component) that computes all six tile values from the current `liens` and `cases` state. Single derivation pass — don't compute each tile separately. Pseudo:

```js
const analytics = useMemo(() => {
  const enrichedLiens = liens.map(deriveLienAnalytics);
  const allLiens     = enrichedLiens;
  const activeLiens  = enrichedLiens.filter(l => l.status === 'Active');
  const settledLiens = enrichedLiens.filter(l => l.status === 'Settled');

  const totalDeployed = sumBy(allLiens, l => l.purchasePrice);
  const totalAtRisk   = sumBy(activeLiens, l => l.bill);
  const recoverySum   = sumBy(settledLiens, l => l.recovery);
  const purchaseSum   = sumBy(settledLiens, l => l.purchasePrice);
  const recoveryRate  = purchaseSum > 0 ? (recoverySum / purchaseSum) * 100 : null;

  const avgDaysToSettle = settledLiens.length === 0 ? null :
    sumBy(settledLiens, l => daysBetween(l.ts, l.settledAt)) / settledLiens.length;

  const activeCases  = cases.filter(c => c.status === 'Active');
  const settledCases = cases.filter(c => c.status === 'Settled');

  return {
    totalDeployed,
    totalAtRisk,
    recoveryRate,
    avgDaysToSettle,
    activeCases: { count: activeCases.length, lienCount: activeLiens.length },
    settledCases: { count: settledCases.length, recoverySum },
    counts: { all: allLiens.length, active: activeLiens.length, settled: settledLiens.length },
  };
}, [liens, cases]);
```

This same derivation gets reused in Commit 2 for the charts and aging table.
